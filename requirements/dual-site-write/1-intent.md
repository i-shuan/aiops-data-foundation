# Intent — 兩廠雙寫

> 內容已在對話中確認。總綱見
> [`multi-site-metrics-write`](../multi-site-metrics-write/1-intent.md) 的拆法第 3 項。

## 解決誰的什麼問題

中科、二林各有一座中央的 VictoriaMetrics。現在每個 cluster 的 vmagent 只寫
其中一座，那一座停機或跨廠網路斷掉的期間，該 cluster 的監控資料就沒了，而且
事後補不回來。

## 不做會怎樣

| 現況 | 代價 |
| --- | --- |
| 只有一個目的地 | 那一座停機時，這段時間的資料永久遺失 |
| 暫存放在 pod 裡 | vmagent 一重啟，排隊中的資料就沒了，不報錯 |
| 資料上沒有廠區 | 同一個部門在兩廠的資料進同一個租戶後分不出來 |

## 成功長什麼樣

本機 k3d 上，同一個 namespace 的樣本同時出現在兩座的同一個 AccountID，帶著
`site`；停掉其中一座幾分鐘、中間重啟 vmagent、再恢復，那一座在停機期間的
樣本數跟沒停的那座一樣。

## 明確不做什麼

| 不做 | 為什麼 |
| --- | --- |
| 查詢端在兩座之間切換 | 總綱已列為不做。⚠️ 補送完成前，剛恢復的那座查得到的資料有缺口 |
| 兩座 VictoriaMetrics、vmauth 的部署 | 不在這個 repo |
| 暫存快滿時的告警 | `vmstack-values.yaml` 的告警元件是關的。只在文件寫要看哪個指標 |
| 把新設定套到 AP1105 | 拆法第 4 項 |
| 實際量正式環境的資料量來定暫存大小 | 本機量不出來。給算法與起始值，上線時在該 cluster 量 |
| 兩個廠區各一套 vmagent 同時跑的測試 | 本機只起一套。兩廠的設定除了 `site` 的值以外一樣 |
