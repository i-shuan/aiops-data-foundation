# Intent — trace 經同一套收集程式進 Elasticsearch

> 這一份要人確認之後，才寫 `2-spec.md`。總綱見
> [`elastic-unified-observability`](../elastic-unified-observability/1-intent.md) 的拆法第 4 步。
> 已定（2026-10-06）：程式這一側用 OpenTelemetry 的自動埋點，不用 eBPF。

## 解決誰的什麼問題

IT 維運人員。數值告訴他們「有事」，log 告訴他們「為什麼」，但服務互相呼叫時，
他們不知道「慢或錯在哪一段」。現在 `demo-web` 變慢，分不出是它自己慢還是它呼叫的 `demo-api` 慢。
之後做找根因的人也需要「誰呼叫誰」這張關係圖，這張圖只能從 trace 來。

## 不做會怎樣

| 現況 | 代價 |
| --- | --- |
| 範例程式只在 log 裡印一個自己產生的編號，沒有送出 trace | 看得到兩支程式的 log 是同一次請求，但看不到每一段花多久 |
| 沒有「誰呼叫誰」的資料 | 找根因那一步沒有東西可以用，只能靠人記得系統怎麼接 |
| 沒有試過不改程式碼的做法 | 不知道各部門要配合到什麼程度，沒辦法跟他們談 |

## 成功長什麼樣

本機 k3d 上，範例程式用 OpenTelemetry 的自動埋點送出 trace，經收集程式進到 Elasticsearch，而且：

| 檢查 | 預期 |
| --- | --- |
| 程式碼 | 範例程式不為了 trace 寫任何一行送出的程式。只改啟動方式或部署設定 |
| 一次請求 | `demo-web` 與 `demo-api` 的每一段在同一筆 trace 裡，看得出誰呼叫誰、各花多久 |
| 分部門 | 跟數值、log 同一套規則：照 namespace 的門牌，沒掛或寫錯的進 `platform` |
| 標籤 | 每一段帶 `tenant`、`dept`、`system`、`site`、`cluster`，值跟同一個 pod 的數值、log 一樣 |
| 把 `demo-api` 弄慢 | 從 `demo-web` 的那筆 trace 看得出時間花在 `demo-api` 那一段 |
| 串到 log | 拿 trace 的編號去查 log，查得到同一次請求在兩支程式的 log |
| 程式自稱別的部門 | 不算數，照門牌走 |
| 停掉 Elasticsearch 再開回來 | 停機期間的 trace 補回來 |
| 誰呼叫誰 | 從 Elasticsearch 裡的 trace 查得出「`demo-web` 呼叫 `demo-api`」這條關係 |

## 明確不做什麼

| 不做 | 為什麼 |
| --- | --- |
| eBPF | 已定不用 |
| 抽樣（只留一部分的 trace） | 總綱的分層保留，另外開。這一步全收 |
| 把「誰呼叫誰」畫成圖、算成固定的資料表 | 這一步只確認查得出來。怎麼整理成找根因用的樣子是第 5 步 |
| 真的系統（MES、ERP）的埋點 | 這一步只用範例程式試出做法。各系統用什麼語言、怎麼導入要另外談 |
| Python 以外的語言 | 範例程式是 Python。Java、.NET 的自動埋點做法類似，但這裡驗不到 |
| 資料庫、訊息佇列的 trace | 範例程式沒有用到 |
| 誰能看哪個部門的 trace、Kibana 的畫面 | 跟前兩步一樣 |

## 還沒談定的 ❓

| # | 問題 | 我的建議 |
| --- | --- | --- |
| 1 | 自動埋點怎麼放進程式 | 用 OpenTelemetry Operator：在 pod 上加一個標註，它在 pod 啟動時自動把埋點塞進去，image 不用改。這最接近「平台統一做、各部門只加一行」。代價是 cluster 要多裝 Operator 與它需要的 cert-manager。另一個做法是把埋點包進 image、改啟動指令，不用裝東西，但每個 app 都要自己改 |
| 2 | 範例程式要不要改 | 要小改。它現在用 Python 內建的最陽春的網頁伺服器，還自己手寫傳編號。自動埋點認得的是常見的框架，所以要換成一個常見的框架，並把手寫傳編號的那段拿掉。這跟真的系統的情況一樣：自動埋點只對它認得的框架有效 |
| 3 | log 裡的編號 | 改成由自動埋點填進 log，不再自己產生。這會動到上一步驗過的「同一個編號兩邊都查得到」，要重驗 |
| 4 | trace 由哪一份收集程式收 | 節點那一份。程式送給自己所在節點的那一個，不用跨節點，節點那一份也已經有讀門牌的規則。cluster 那一份不動 |
| 5 | 收集程式開的入口要不要驗身分 | 這一步不驗，只收 cluster 裡面來的。誰都能送，所以擋冒充跟數值、log 一樣靠「只認門牌」 |
