# writing — 寫文件的規則

前四條由專案的 md 格式檢查器把關（指令見 `.agents/project/commands.md`）。

| | 規則 |
| --- | --- |
| ① 粗體 | 只給核心名詞、最終決策、錯誤碼。**禁止加粗副詞**（完全／一律／千萬／絕對／務必）。改法是把語氣換成事實 |
| ② 反引號 | 檔名、變數、函數、路徑、設定 key、指令一律包 |
| ③ 資訊降維 | 純文字連續上限 **3 行**；並列概念超過 2 個改表格 |
| ④ 警告分級 | 每節（算到最小層級標題）至多 1 個 blockquote，其餘降成行內 `⚠️` |
| ⑤ 禁止行銷詞 | 賦能、抓手、閉環、頂層設計、全方位、深度整合、一站式、生態、數位轉型 |
| ⑥ 指令要能照貼 | 從 repo 根目錄貼進終端機就能跑。要換目錄就把 `cd` 寫進同一個區塊 |
| ⑦ 每份都要有「會安靜壞掉的地方」 | 寫法是三件一組：**症狀 → 原因 → 為什麼沒人會發現** |
| ⑧ 架構圖用 Mermaid | 中文佔兩格，手動數空格的 ASCII 框線圖一定會歪。檔案樹例外 |

文風基準看專案的踩坑文件。專有名詞保留英文，不要硬翻。

## 警告放哪

| 種類 | 放哪 |
| --- | --- |
| 跨檔重複的鐵律 | 踩坑文件的「跨檔的鐵律」當唯一正本，別處只留摘要加連結 |
| 只在一處成立的 | 留在它描述的那段東西**旁邊**。搬到文末表格會失去上下文 |

## 改了行為，要寫回文件

⚠️ 沒做這一步是這個 repo 最常發生的失敗。症狀是「文件寫的跟程式做的不一樣」，
而且**所有自動檢查都是綠的** —— 檢查器抓得到連結壞掉、格式違規，但抓不到
「敘述過期而關鍵字還活著」。實際發生過三次。

| 改了什麼 | 要檢查 |
| --- | --- |
| 使用者看得到的行為 | 架構文件對應那節 |
| 指令、腳本、環境變數 | `.agents/project/commands.md` |
| 部署、映像檔、設定檔 | 上線文件、`.agents/project/deploy.md` |
| 發現「做錯了不報錯」的坑 | 踩坑文件 |
| 讓某個舊敘述失效 | 搜那個關鍵字，所有提到的地方一起改 |

收尾要有一行：**動到的文件 / 確認過沒過期的 / 沒動文件的理由**。
「沒動文件」是合法答案（純 bug 修正、重構、改錯字），但要講出來。

## 加檢查工具的時候

* 兩個方向都要測：該響的時候響，**不該響的時候不響**
* 一個會誤報的檢查很快就會被所有人忽略，**比沒有更糟**
* 架構改了要同步「過期引用」清單：死掉的加進去，**活回來的移出去**
