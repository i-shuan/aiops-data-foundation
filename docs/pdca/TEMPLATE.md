# <主題>（YYYY-MM）

> 複製這份，改檔名成 `YYYY-MM-主題.md`，刪掉每段的提示；沒有的寫「無」，不要整段刪。
> 一份記**一輪**（一個需求、一次改動）。事實要能對到程式、設定或實測（附路徑或指令）；沒驗證的寫「未驗證」，推論的寫「推論」。
> **不要寫「N 個測試通過」**：數字不告訴人測了什麼、證明了什麼。寫「為了確認什麼、做了什麼測試、發現什麼」。

**狀態**：進行中 ／ 已完成 ／ 放棄　　**日期**：YYYY-MM-DD　　**相關**：分支、PR、commit

## Plan：這一次要達到什麼

- **需求**：誰、在什麼情況下、遇到什麼問題（一兩句，講現象，不講解法）
- **目的**：做完之後要變成什麼樣（可以對照驗證的）
- **範圍**：這次做什麼、不做什麼

## Do：改動哪些 code、改了什麼、為何要改

每個檔案一列。「為何」要寫到讀的人能判斷這樣改對不對，不是重述「改了什麼」。

| 檔案 | 改了什麼 | 為何要改 |
|---|---|---|
| | | |

不是 code 的改動（文件、設定）也列。沒有改 code（只做實驗、只改文件）就寫「無 code 改動」，並說明做了什麼。

## Check：測試的目的與結果

每一項寫「為了確認什麼」、「怎麼測」、「結果」。結果要有觀察到的內容（數字、現象、錯誤訊息），不要只寫「通過」。

| 測試目的（為了確認什麼） | 怎麼測 | 結果 |
|---|---|---|
| | | |

- 測的過程中**發現的問題**（程式的 bug、設計漏洞）和怎麼處理，寫在這裡或 Act。
- 有多個做法要比較時，附比較表（怎麼運作、要多少工、風險、效果）。
- **沒測到的**：列出來。

## Act：Check 後沒改善的、還沒解決的

每一項寫「是什麼」、「**在什麼情況下發現的**」、「影響」、「打算怎麼處理」。沒有證據的不要列。

| 沒改善的 | 在什麼情況下發現的 | 影響 | 後續 |
|---|---|---|---|
| | | | |

- **決定**：採用／不採用什麼，一句話理由。
- **下一輪**：要驗證或要做的，連到 [README.md](README.md) 的待辦。
