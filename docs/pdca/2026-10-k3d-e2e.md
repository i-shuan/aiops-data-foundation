# k3d 上的 K8s 實測：Grafana initContainer、Collector 補身分、OTLP log（2026-10）

**狀態**：完成（k3d 單節點，四件事都跑過）　　**日期**：2026-10-27　　**相關**：分支 `claude/k3d-e2e`；補 [grafana-plugin-init](2026-10-grafana-plugin-init.md)、[ingest-keys-check](2026-10-ingest-keys-check.md) 的 Act「K8s 上沒跑過」
**模組**：①②③、⑧

## Plan：這一次要達到什麼

- **需求**：前兩份驗證都是在 docker 裡做的（沒有 K8s）。留下三個「K8s 上沒驗」：(1) Grafana 的 initContainer 在 Pod 裡的行為；(2) Collector 用 `k8s_attributes` 依 Pod 補身分（namespace、Pod、部門、服務名稱）；(3) 真的 `app-common` chart 部署的應用，`otel.logs.exporter: otlp` 在 K8s 上通不通。另外 chart 的新選項沒用 `helm template` 驗過。
- **目的**：用 k3d 起一個本機 K8s，把這四件事各跑一次，結果寫進 Check；把「怎麼在這個環境起 k3d」存成腳本（`e2e/local-k3d/`），以後可以重跑。
- **範圍**：單節點 k3d；ES 用主機 docker 的測試 ES（接到 k3d 的網路）；Nexus 用主機上的 HTTP 服務代替。不做壓測、不做多節點。

## Do：改動哪些 code、改了什麼、為何要改

無 code 改動（測試的是前面各分支已經合進 master 的東西）。新增的是 k3d 的建置腳本：

| 檔案 | 內容 | 為何 |
|---|---|---|
| `e2e/local-k3d/create-cluster.sh`、`containerd-config.toml.tmpl` | 單節點、無 loadbalancer／traefik／servicelb；containerd 設 `restrict_oom_score_adj = true` | 這個環境沒有 `CAP_SYS_RESOURCE`，kubelet 把 Pod sandbox 的 oom_score_adj 調成 -998 會被拒，所有 Pod 起不來 |

## Check：測試的目的與結果

k3d v5.8.3（k3s v1.31.5）、kubectl 1.31.5、helm 3.16.4，都核對過官方的 SHA-256。ES 是主機 docker 的 9.5.5，接到 k3d 的網路；Nexus 用主機上的 HTTP 服務代替。

| 目的 | 怎麼測 | 結果 |
|---|---|---|
| chart 的 `otel.logs.exporter`（前一輪沒驗） | `helm template`：預設、`otlp`、.NET＋`otlp`、亂填；`sdk/ci/validate-charts.sh` | 預設 `none`、沒有 logs endpoint；`otlp` 多 `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT`、協定；Java、.NET 都對；亂填 `stdout` 會失敗；CI 檢查過 |
| Grafana initContainer 在 Pod 裡 | `grafana-example.yaml`（Nexus 網址指到主機）部署 | initContainer 下載、核對、解開；Grafana 起來，外掛 6.3.1 `signature: valid`，儀表板「AIOps / AIOps 回饋」載入 |
| Pod 重建自動重裝 | 刪 Pod | 新 Pod 的 initContainer 又裝一次，起得來 |
| SHA-256 不符 | 把 `PLUGIN_SHA256` 改錯 | 新 Pod 停在 `Init:Error`，log 寫「SHA-256 不符：預期…下載到的是…」；**舊的健康 Pod 繼續服務**：壞的更新不會把 Grafana 弄掛 |
| 平台 Collector 在 K8s 上 | `kubectl apply -k`（node DaemonSet、cluster、trace-sampler ×2 含 PVC） | 全部 Running |
| Collector 依 Pod 補身分（`k8s_attributes`） | 用真的 `app-common` chart 部署 Java 應用（Tomcat JSP，`java.util.logging` 純文字，程式沒有 OpenTelemetry），namespace `mes-prod` 標 `dept=D3120` | trace：`service.name: mes-api`（Pod 的 `app.kubernetes.io/name` label，chart 蓋的）、namespace、Pod 名、`dept: D3120`、`group: it`、`cluster: local`，進 `traces-generic.otel-it` |
| OTLP log 在 K8s 上（`logs/otlp`） | 同一個應用 `otel.logs.exporter: otlp` | log 進 `k8s-it-local`：`trace_id`、`span_id`、`log.level`、`service.name`、`kubernetes.namespace/pod.name`、`labels.dept/group` 都在；錯誤那行用 `trace_id` 查 traces 找到 `GET /index.jsp` 的 Server span，`span_id` 一樣 |
| 開 otlp 會有兩份 log（前一輪預期的） | 數 `order … handled` | 53 筆：agent 直送 23 筆（有 trace_id）、容器 log 檔收的 30 筆（沒有）。**確認有兩份** |

## Act：Check 後沒改善的、還沒解決的

- **兩份 log 還沒處理**（在什麼情況下發現：上面最後一列）：同一行 log 檔案那份和 agent 那份都進 ES，AIOps 看 log 樣式、算次數會重複。要嘛 filelog 對開了 otlp 的 Pod 不收（依 Pod 的 annotation 或 label 排除），要嘛查詢時只取有 trace_id 的那份。先在文件寫清楚，試點看量再決定。
- **.NET 沒在 K8s 上跑**：這次 K8s 上只有 Java。.NET 的 chart 渲染驗過（`helm template`），agent 直送在 docker 驗過，K8s 上的 .NET 要再跑一次（`e2e/local-k3s/dotnet-app` 設 `otel.logs.exporter: otlp`）。
- **這是 k3d 的單節點**：多節點、DaemonSet 在每個節點補身分、trace-sampler 兩台之間依 trace_id 分配，這次只有一個節點。
- **kubeletstats、cadvisor 的 metrics 沒看**：Collector 起得來、沒報錯，但這次沒檢查這兩條有沒有資料。
- **k3d 的限制是這個環境的，不是產品的**：`restrict_oom_score_adj`、匯入 image 是因為這台沒有 `CAP_SYS_RESOURCE`、proxy 換憑證；正常環境直接 `k3d cluster create` 就好，腳本裡寫了原因。
- 沒有 Grafana 回饋表單在 K8s 裡的 Grafana 上跑（只驗了外掛載入和儀表板）：表單要連回饋服務，回饋服務還沒放進 k3d。
