# 共同鑰匙圈在 K8s 上：三種資料的鑰匙值一不一樣（2026-10）

**狀態**：已完成　　**日期**：2026-10-27　　**相關**：分支 `claude/p1-keys-c8d79e`；[ingest-keys-check](2026-10-ingest-keys-check.md)（docker 驗過的部分）、[field-unify](2026-10-field-unify.md)
**模組**：① 收值、② 清資料

## Plan：這一次要達到什麼

- **需求**：docker 驗過「同一組路徑查得到」，但 K8s 上鑰匙的值由 Collector 依 Pod 補，邊緣情況（沒 label、應用自己取名、冒充、改部門、Pod 換掉、hostNetwork）沒驗過。
- **目的**：同一個請求的 trace、log、metrics，用 `service.name`、`k8s.namespace.name`、`k8s.pod.name`、`dept`、`group`、`k8s.cluster.name` 交叉查得到，值一樣；每個邊緣情況有預期、有實測。
- **範圍**：在本機 k3s（Rancher Desktop，單節點）跑。不測多節點、不測 Fluent Bit 那條路。

五種資料（同一個請求同時產生）：

| 代號 | 怎麼進來 | 鑰匙由誰補 |
|---|---|---|
| trace | OTLP 推給同節點 Collector → trace-sampler | Collector 依連線來源 IP 找 Pod |
| log_stdout | stdout JSON，Collector 讀容器 log 檔 | Collector 依 log 檔路徑（Pod UID） |
| log_otlp | OTLP log record（`otel.logs.exporter: otlp`） | Collector 依連線來源 IP |
| met_prom | Collector 抓 `/metrics` | Collector 依抓取對象的 IP |
| met_otlp | OTLP 推（.NET 的做法） | Collector 依連線來源 IP |

## Act：Check 後沒改善的、還沒解決的

| 沒改善的 | 在什麼情況下發現的 | 影響 | 後續 |
|---|---|---|---|
| [①] trace-sampler 2 台時 trace 幾乎全丟 | K8s 上 trace 一筆都沒進 ES | 所有 trace；重啟 node Collector 沒用（連續 6 次） | 交給 trace 不掉資料的任務決定怎麼修（見下） |
| 新 Pod 剛起來的第一筆 OTLP 進 unassigned | 情境「落到 unassigned」 | 每個新 Pod 每種約 1 筆，沒有 Pod 名字 | 不修：Pod IP 進清單前沒辦法知道是誰 |
| hostNetwork 的 OTLP 對不到 Pod | 情境 hostNetwork | trace、OTLP log、OTLP metrics 進 unassigned | 維持「應用不能用 hostNetwork」 |
| 對不到 Pod 的 OTLP log，內容、時間一樣會被當重複 | 兩個 hostNetwork Pod 訊息相同時，hostnet2 的 OTLP log 0 筆 | 只有對不到 Pod 的（上兩列）會撞 | 測試訊息改帶情境名稱後通過；去重複的原料沒改 |
| Pod 刪掉時 Collector 印 `Dropping data` | 換 Pod 後看 Collector log | `send_failed_metric_points` 增加，看起來像遺失 | 監控時排除；或在 Collector 先濾掉 |
| 裸 Pod（沒有 Deployment、沒有 label） | 讀程式（推論） | metrics、trace 沒有 `service.name`；log 用 container 名稱 | 沒測；目前都用 Deployment |

- 第一列的原因：每台 trace-sampler 一個子 exporter，磁碟佇列卻是同一個檔（`/var/lib/otelcol/node/exporter_otlp_grpc_traces_traces`）。
- 第二個子 exporter 開檔等鎖逾時（`failed to start new exporter ... "error": "timeout"`），之後不重試，含送往那台的 trace 整批被拒。
- 第一列來自 `node.yaml` 的 `loadbalancing/traces` 子 exporter 設 `storage: file_storage`（[trace-durability](2026-10-trace-durability.md)）；怎麼修是 trace 不掉資料的設計決定，這次不改。
- `run-keys-e2e.sh` 用 `ONE_SAMPLER=1` 繞過：測試期間 trace-sampler 縮成 1 台，結束恢復。
- **決定**：`service.name` 一律以 Pod label 為準。label 是平台（chart）蓋的，log 只能用它；應用自設的只在沒 label 時用。
- **決定**：沒改 Collector 的分部門規則：冒充、沒 dept、dept 不在清單、改 dept、同名服務都照預期。
- **下一輪**：修第一列後拿掉 `ONE_SAMPLER` 重跑；多節點時 trace 跨節點、各節點 Collector 的清單。
