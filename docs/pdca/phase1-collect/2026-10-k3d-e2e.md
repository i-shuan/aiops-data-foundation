# k3d 上的 K8s 實測：Grafana initContainer、Collector 邊緣身份鑑別與標籤注入 (Edge Identity Sanitization & Injection)、OTLP log（2026-10）

**狀態**：完成（k3d 單節點，四件事都跑過）　　**日期**：2026-10-27　　**相關**：分支 `claude/k3d-e2e`；補 [grafana-plugin-init](../phase5-learning-loop/2026-10-grafana-plugin-init.md)、[ingest-keys-check](2026-10-ingest-keys-check.md) 的 Act「K8s 上沒跑過」
**模組**：①②③、⑧

## Plan：這一次要達到什麼

- **需求**：前兩份驗證都在 docker 裡做，留下四件 K8s 上沒驗的事：
  1. Grafana 的 initContainer 在 Pod 裡的行為。
  2. Collector 用 `k8s_attributes` 依 Pod 注入身分標籤（namespace、Pod、部門、服務名稱）。
  3. 真的 `app-common` chart 部署的應用，`otel.logs.exporter: otlp` 在 K8s 上通不通。
  4. chart 的新選項沒用 `helm template` 驗過。
- **目的**：用 k3d 起本機 K8s，四件事各跑一次；起 k3d 的方法存成腳本（`e2e/local-k3d/`），以後可以重跑。
- **範圍**：單節點 k3d；ES 用主機 docker 的測試 ES（接到 k3d 的網路）；Nexus 用主機上的 HTTP 服務代替。不做壓測、不做多節點。

## Do：改動哪些 code、改了什麼、為何要改

無 code 改動（測的是前面各分支已合進 master 的東西）。新增 k3d 的建置腳本：

| 檔案 | 內容 | 為何 |
|---|---|---|
| `e2e/local-k3d/create-cluster.sh`、`containerd-config.toml.tmpl` | 單節點、無 loadbalancer／traefik／servicelb | — |
| 同上 | containerd 設 `restrict_oom_score_adj = true` | 這個環境沒有 `CAP_SYS_RESOURCE`，否則所有 Pod 起不來 |

- 沒有 `CAP_SYS_RESOURCE` 時，kubelet 把 Pod sandbox 的 oom_score_adj 調成 -998 會被拒。
- `k3d image import` 會失敗：多平台索引缺 blob。

## Check：測試的目的與結果

k3d v5.8.3（k3s v1.31.5）、kubectl 1.31.5、helm 3.16.4，都核對過官方的 SHA-256。ES 是主機 docker 的 9.5.5，接到 k3d 的網路；Nexus 用主機上的 HTTP 服務代替。

| 目的 | 怎麼測 | 結果 |
|---|---|---|
| chart 的 `otel.logs.exporter` | `helm template`：預設、`otlp`、.NET＋`otlp`、亂填 | 預設 `none`、沒有 logs endpoint |
| 同上 | 同上 | `otlp` 多 `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT`、協定；Java、.NET 都對 |
| 同上 | 同上＋`sdk/ci/validate-charts.sh` | 亂填 `stdout` 會失敗；CI 檢查過 |
| Grafana initContainer 在 Pod 裡 | `grafana-example.yaml`（Nexus 網址指到主機）部署 | initContainer 下載、核對、解開 |
| 同上 | 同上 | 外掛 6.3.1 `signature: valid`；儀表板「AIOps / AIOps 回饋」載入 |
| Pod 重建自動重裝 | 刪 Pod | 新 Pod 的 initContainer 又裝一次，起得來 |
| SHA-256 不符 | 把 `PLUGIN_SHA256` 改錯 | 新 Pod 停在 `Init:Error`，log「SHA-256 不符：預期…下載到的是…」 |
| 同上 | 同上 | **舊的健康 Pod 繼續服務**：壞的更新不會把 Grafana 弄掛 |
| 平台 Collector 在 K8s 上 | `kubectl apply -k`（node DaemonSet、cluster、trace-sampler ×2 含 PVC） | 全部 Running |
| Collector 依 Pod 注入身分標籤（`k8s_attributes`） | 真的 `app-common` chart 部署 Java 應用（見下） | trace 進 `traces-generic.otel-it` |
| 同上 | 同上 | `service.name: mes-api`、namespace、Pod 名、`dept: D3120`、`group: it`、`cluster: local` |
| OTLP log 在 K8s 上（`logs/otlp`） | 同一個應用 `otel.logs.exporter: otlp` | log 進 `k8s-it-local` |
| 同上 | 同上 | `trace_id`、`span_id`、`log.level`、`service.name` 都在 |
| 同上 | 同上 | `kubernetes.namespace/pod.name`、`labels.dept/group` 都在 |
| 同上 | 錯誤那行用 `trace_id` 查 traces | `GET /index.jsp` 的 Server span，`span_id` 一樣 |
| 開 otlp 會不會有兩份 log | 數 `order … handled` | **有兩份**：53 筆＝agent 直送 23 筆（有 trace_id）＋容器 log 檔 30 筆（沒有） |

- Java 應用：Tomcat JSP，`java.util.logging` 純文字，程式沒有 OpenTelemetry；namespace `mes-prod` 標 `dept=D3120`。
- `service.name` 來自 Pod 的 `app.kubernetes.io/name` label（chart 蓋的）。
