# 功能積木化：④⑥⑦⑨ 每一段一張積木登記表，情境資料檔選要哪幾塊（2026-11）

**狀態**：已完成　　**日期**：2026-11-07　　**相關**：分支 `claude/blocks`（從 `claude/remove-rca-eval` 開，那條還沒合回 master）
**模組**：④ 判斷、⑥ 收斂、⑦ 根因分析、⑨ feedback

## Plan

- **需求**：使用者要「所有程式功能積木化」；選了「介面＋登記表＋yaml 選」（不拆成獨立套件），四段都做（④→⑥→⑦→⑨）。
- **現在已經是積木的**：來源適配器（`data/source/`）、根因報告的段落（情境的 `sections`）、跨服務併件與換版（情境的 `chain`、`change`）、排程表。
- **目的**：每一段的功能是一塊一塊的：①看得到有哪些塊、哪些開著（`detector blocks`）；②情境資料檔的 `blocks:` 選要哪幾塊、關掉哪幾塊，不改程式；③可以填自己寫的實作（`套件.模組:名字`），跟現在的 `chain`、`commands` 同一種寫法；④沒寫 `blocks:` 的跟現在一模一樣。
- **範圍**
  - 共用：`common/blocks.py` 登記表（名字 → `模組:名字`，第一次用才載入；不認得的名字講清楚有哪些）；`Scenario.blocks`。
  - ④：判斷方法與序列的前處理各一塊（動態基準線學習、Pod 同儕橫向比對、靜態臨界值規則、慢性病清單、資料品質檢查、一階跳變、trace 每段），關掉的那個指令跑了只印一行、回 0（排程照跑不會報錯）。手動調整（排除時段、重置點）是動態基準線的一部分，不單獨開關。
  - ⑥：併件一塊（同對象）；嚴重度是一串積木（黃金訊號評分 → P0 升一級），可以換、可以加。
  - ⑦：報告段落沿用 `sections`、可以填自己的段落；相似事故（欄位比對、向量）、LLM 摘要、歷史線索與先查清單各一塊。
  - ⑨：回饋建議（誤報、漏報、整條序列的準確率、升級成規則）與一句話抽建議各一塊，可以加自己的建議規則。
- **不做**：拆成獨立安裝的套件；積木之間的相依檢查（例如關掉相似事故，先查清單照樣能用預設清單）。

## Act

- **只做了 ④⑥⑦⑨**：① 收值不在 repo，② 的來源適配器本來就是積木（`data/source/`）；③ 存（資料庫）、⑧ 出口（Grafana）沒有做成積木。
- **積木之間沒有相依檢查**：例如關掉 `fields`、只開 `vector` 又沒設 embedding，相似事故就是空的，不會警告；`detector blocks` 看得到開了哪些。
- **④ 是「指令要不要跑」**：關掉的指令還是在排程表裡、每輪印一行；要省這一行就把排程表的那個工作也拿掉。
