# SonarQube 第一次掃：把會誤導的報掉、真的問題修掉（2026-10）

**狀態**：完成（本機 SonarQube Community 26.10 實掃兩次：修前、修後）　　**日期**：2026-10-29　　**相關**：分支 `claude/sonar-fixes`；`sonar-project.properties`
**模組**：跨階段（engine ④～⑨、engine/deploy ⑧）

## Plan：這一次要達到什麼

- **需求**：沒有掃過。第一次掃出 121 個 vulnerability、5 個 bug，看起來很糟，但要分清楚哪些是真的、哪些是測試環境的設定被當成正式程式。
- **目的**：掃描範圍固定下來（可重跑），真的問題修掉，剩下的每一個都寫清楚為什麼不修。
- **範圍**：只修 Sonar 報的；不順手重構、不動 `e2e/`（它本來就是模擬環境，故意不設 limits、寫 `/tmp`）。

## Do：改動哪些 code、改了什麼、為何要改

| 檔案 | 改了什麼 | 為何要改 |
|---|---|---|
| `sonar-project.properties`（新） | sources 只掃 `engine`、`telemetry`、`sdk`；`engine/tests` 當測試；覆蓋率讀 `coverage.xml` | 第一次掃 121 個 vulnerability 裡 110 個在 `e2e/`：模擬服務的 manifest 故意沒 limits、用 busybox、寫 `/tmp`。它不是正式程式，掃了只會蓋掉真的問題 |
| `engine/core/llm.py`、`detector/chronic.py`、`detector/quality.py` | NaN 判斷從 `v != v` 改成 `math.isfinite`／`pd.isna` | Sonar 把 `v != v` 當 bug（S1764 兩邊一樣）。原本是對的（NaN 不等於自己），但改成明講的寫法，之後看的人也不用想 |
| `engine/core/es.py` `doc_id` | `hashlib.sha1(..., usedforsecurity=False)` | sha1 在這裡只是算 `_id`，不是安全用途（S4790）。**不能換演算法**：換了既有資料的 `_id` 全變、寫入會重複 |
| `engine/feedback_web/__main__.py` | 給 `FEEDBACK_TLS_CERT`／`FEEDBACK_TLS_KEY` 就走 https | 原本只有 http（S5332）。正式放 Ingress 後面由 Ingress 做 TLS，但沒有 Ingress 直接對外時要有辦法 |
| `engine/deploy/grafana/grafana-example.yaml` | `automountServiceAccountToken: false`；兩個容器加 `ephemeral-storage` request／limit | Grafana 不用呼叫 K8s API，token 不該掛（S6865）；範例沒掛 PVC，sqlite、log 都在容器裡，要有上限（S6870） |
| `engine/deploy/grafana/plugin-init-patch.yaml` | initContainer 加 `ephemeral-storage`；主容器加註解「這個 patch 不動 resources 和 service account」 | 它是 strategic merge patch，主容器的 resources、SA 是公司 Grafana 原本的設定。**不加 `automountServiceAccountToken: false`**：用 Helm chart 裝的 Grafana 常有 sidecar 靠 K8s API 讀 ConfigMap，關掉會壞 |
| `.gitignore` | `coverage.xml`、`.coverage` | 掃描前產生的，不進 repo |

## Check：測試的目的與結果

本機 SonarQube Community 26.10.0（docker，H2），sonar-scanner-cli；覆蓋率用 `pytest --cov`（346 個測試全過，修前修後都是）。

| | 修前（掃全部） | 修後（`sonar-project.properties`） |
|---|---|---|
| 掃的行數 | 8,431 | 5,323（少掉 `e2e/`） |
| Bug | 5 | **0** |
| Vulnerability | 121 | **4**（下表） |
| Security hotspot | 0 | 0 |
| Code smell | 125 | 4 |
| 覆蓋率 | 42.2% | 54.7%（分母少了 `e2e/`，不是測試變多） |
| 可靠性／安全／維護性 | C／D／A | A／C／A |
| 品質閘門（Sonar 預設） | OK | OK（接受 1 個 S5332 之後；見下） |

| 目的 | 怎麼驗 | 結果 |
|---|---|---|
| `doc_id` 加 `usedforsecurity=False` 後 `_id` 不變 | 同一組參數，跟原本的 `hashlib.sha1(...).hexdigest()` 比 | 一樣 |
| NaN 判斷改寫後行為一樣 | `_num(nan/inf/'x'/'1.5')` → None/None/None/1.5；`chronic.describe`、`quality.describe` 丟 NaN 的 key | 「（無）」、「沒有 ns」照舊 |
| https 真的能開 | 自簽憑證起 `feedback_web`，`curl --cacert` 打 `/health` | 200 `ok`；沒給憑證仍是 http |
| manifest 還是合法 YAML | `yaml.safe_load_all` | 兩個檔都過 |

修後剩的 4 個 vulnerability、4 個 code smell，全部看過：

| 規則 | 在哪 | 為什麼不修 |
|---|---|---|
| S5332 http | `feedback_web/__main__.py` | TLS 是選用的（看環境變數），Sonar 看不出來。正式由 Ingress 做 TLS。在 Sonar 標「接受」並留言 |
| S6865／S6864／S6870／S6892／S6873／S6897 | `plugin-init-patch.yaml` 主容器 | 它是 patch 片段，主容器只加掛載點；resources、SA 是公司原本的。加上去反而會蓋掉人家的設定 |
| S3516 永遠回同一個值 | `cmd_baseline.py` `cmd_tune` | CLI 的 `cmd_*` 都回 exit code，這支沒有失敗路徑所以永遠 0。改了反而跟其他指令不一致 |

## Act：Check 後沒改善的、還沒解決的

| 沒改善的 | 在什麼情況下發現的 | 影響 | 後續 |
|---|---|---|---|
| 品質閘門用 Sonar 預設（new code 覆蓋率 80%、new violation 0） | 第二次掃時閘門變 ERROR：S5332 因為行號移了被算成「新問題」 | 每次改到那行都會紅 | 公司有自己的閘門就套公司的；或把 S5332 在 profile 裡對 `feedback_web` 排除 |
| Java、C# 只有語法層級 | 沒編譯（`e2e/` 的 Java、.NET 範例） | 現在已不掃 `e2e/`，沒影響；之後 `sdk/` 若放 Java／C# 範例要補 | 到時再加 build |
| `telemetry/`、`sdk/` 沒有單元測試，覆蓋率只算 `engine` | 覆蓋率 54.7% 是 engine 的數字 | 看起來比實際高 | 那兩個是 YAML／shell／chart，用 e2e 驗，不補單元測試 |
| ruff 0.16 預設規則下有一大串警告（import 排序、`except Exception`） | 合 master 前跑 ruff | 跟 Sonar 無關，master 也一樣 | 另開一輪，先定 `ruff.toml` 再修 |

- **決定**：Sonar 的掃描範圍是 `engine`、`telemetry`、`sdk`；`e2e/` 永遠不掃。剩下的 8 個不修，理由如上。
